# Підключення Cloudflare R2 для галерей фотографів

> Код уже на проді й чекає лише на змінні середовища. Поки їх немає — усе
> працює через Supabase Storage, як раніше. Щойно зʼявляться — **нові**
> завантаження підуть у R2, а старі файли й далі віддаватимуться з Supabase
> (кожен файл памʼятає своє сховище, тому міграція не потрібна).

**Навіщо:** Supabase бере 0,09 долара за гігабайт вихідного трафіку, і саме
трафік робить галереї дорогими — одна весільна галерея коштує близько 40
гривень. Cloudflare R2 не бере за трафік нічого, тож та сама галерея
коштуватиме менше гривні.

---

## Крок 1. Створити бакет

Cloudflare Dashboard → **R2** → **Create bucket**.

- Назва: `touchmemories-galleries`
- Локація: Automatic (або EU, якщо є вибір)

## Крок 2. Увімкнути публічний доступ

Відкрити бакет → вкладка **Settings** → блок **Public access**.

Або через `r2.dev`: натиснути **Allow Access** і скопіювати адресу виду
`https://pub-xxxxxxxx.r2.dev`.

Або підключити власний піддомен (краще для брендування й швидкості):
**Custom Domains** → додати, наприклад, `files.touchmemories.com.ua`.
Тоді публічна адреса — `https://files.touchmemories.com.ua`.

## Крок 3. Створити API-токен

R2 → **Manage R2 API Tokens** → **Create API token**.

- Дозволи: **Object Read & Write**
- Обмежити на бакет `touchmemories-galleries` (не давати доступ до всіх)
- Зберегти **Access Key ID** і **Secret Access Key** — секрет показується
  лише один раз

## Крок 4. Знайти Account ID

Видно на головній сторінці розділу R2, праворуч, або в адресному рядку
дашборда після `/accounts/`.

## Крок 5. Додати змінні у Vercel

Vercel → проєкт **touchmemories1** → **Settings** → **Environment Variables**
(усі — для Production):

| Змінна | Значення |
|---|---|
| `R2_ACCOUNT_ID` | Account ID з кроку 4 |
| `R2_ACCESS_KEY_ID` | Access Key ID з кроку 3 |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key з кроку 3 |
| `R2_BUCKET` | `touchmemories-galleries` |
| `R2_PUBLIC_BASE_URL` | адреса з кроку 2, без слеша в кінці |

Далі **Deployments** → останній деплой → **Redeploy** (змінні читаються під
час збірки й на рантаймі, тож без редеплою вони не підхопляться).

## Крок 6. Перевірка

Завантажити будь-яке фото в галерею через кабінет фотографа і перевірити,
що новий рядок отримав `storage_provider = 'r2'`:

```sql
SELECT file_name, storage_provider, created_at
FROM photographer_gallery_photos
ORDER BY created_at DESC
LIMIT 5;
```

У клієнтській галереї це фото має вантажитися з адреси `R2_PUBLIC_BASE_URL`,
а не з `*.supabase.co`.

---

## Якщо щось піде не так

Прибрати пʼять змінних і зробити redeploy — нові завантаження знову підуть у
Supabase. Файли, які вже потрапили в R2, залишаться доступними, поки в базі
стоїть їхній `storage_provider = 'r2'` і бакет живий.

## Технічні деталі для памʼяті

- Абстракція сховища: `lib/photographers/storage.ts`
  (`putFile`, `presignUpload`, `fileExists`, `removeFiles`, `fileUrl`)
- Колонка `photographer_gallery_photos.storage_provider`
  (`'supabase'` за замовчуванням)
- Фото вантажаться через наш API, відео — напряму в сховище за підписаним
  посиланням (обидва шляхи вже підтримують R2)
- Нічний крон видалення протермінованих галерей чистить обидва сховища
- Файли брендування (лого, аватар, портфоліо) навмисно лишаються на
  Supabase — вони маленькі, і їхні абсолютні URL уже записані в рядках

## Собівартість після переїзду

- Зберігання: 0,015 долара за ГБ на місяць (≈ 0,62 грн)
- Трафік: 0
- Безкоштовно: перші 10 ГБ зберігання

Тарифи, які ми обговорювали: безкоштовно 4 ГБ (собівартість ≈ 2,5 грн/міс),
129 грн за 50 ГБ (собівартість ≈ 31 грн, маржа 76%), і третій тариф на
250 ГБ — обговорити ціну (≈ 155 грн собівартості).
